# 制作、检查与验收契约

适用：制作或修改交付物、检查漏项、诊断运行问题、验收版本。按本次实际范围选检查项，不把所有项目套同一个全量流程。

## 先确定验收对象

把用户当前需求和仍在范围内的约束对应到目标文件 / 页面、验证动作与预期结果。复杂任务形成简短清单；单点修改直接说明受影响行为即可。

结果状态：

- **通过**：有可复核证据，满足对应预期。
- **未通过**：已经执行，结果不满足；写明现象。
- **未验证**：没执行、缺环境 / 授权，或证据不足；写明原因。
- **不适用**：本次没有该需求或已明确不做；给出理由，不能拿来隐藏失败。

记录证据时包括目标版本或文件、操作 / 命令、结果、时间或运行标识。图片 / 页面描述和自动测试互补，不互相替代。没实际打开的弹窗不能报视觉通过。

## 复用现有检查器

先解析当前已加载的 SKILL.md 所在目录为技能目录，不重新扫描所有技能。下列是命令模板，运行时替换为已确认的绝对路径并引用含空格的参数：

```text
node "<技能目录>/scripts/validate.mjs" "<正则JSON绝对路径>"
node "<技能目录>/scripts/validate-worldbook.mjs" "<世界书JSON绝对路径>"
```

- 只验证本次确有的交付物；没有世界书不要求生成一份来跑检查。
- 正则校验覆盖导入形状、上限、正则编译、标签与 SDK 能力名等；世界书校验覆盖 entries 及条目字段。
- 当前校验器退出码 0 只代表没有 error，仍可能有 warn。保留完整结果，逐项处理或解释告警，不能把退出码 0 改述成零告警。
- 项目已有构建、解析、状态、表面覆盖或性能测试时优先复用。先看脚本是否会生成 / 覆盖文件或写线上数据；只读检查不要无意运行会改目标文件的构建 / 发布脚本。
- 没有必要的行为测试时，制作任务可补最小回归测试；只读检查记录测试缺口，不自行修改项目。
- 校验失败：制作任务在范围内修复；检查 / 验收任务报告问题，不擅自改卡。

## 交互与状态检查

根据涉及的模块选择，完整游戏采用 [stage-game-brief.md](stage-game-brief.md) 的适用基线。

| 范围 | 可观察的验收条件 |
| --- | --- |
| 正文 / 选项解析 | 合法协议与承诺兼容格式能解析；至少第二回合仍生效；流式未闭合块不提前提交状态；宿主先发的空 done 占位不触发错误提示，真正空回复超时后可恢复；空 / 畸形输入可降级 |
| 选项与输入 | 默认点击选项只填舞台内部输入框并聚焦；舞台保持打开、宿主框不被改、没有发出消息；编辑后确认才发送 |
| 发送模式 | 切换 stageDraft / direct 本身不发消息；重复点击有发送锁；上一次未结束时第二次调用按 `BUSY` 处理且不误认为已排队；失败保留草稿。未授权真实模型调用时用本地可控替身测试并注明边界 |
| 设置与弹窗 | 每个承诺入口可打开 / 关闭，设置可读且有反馈；无数据有正式中文空状态；焦点、Escape、返回与重开不丢失应保留的状态 |
| 多槽存档 | 两份内容不同的快照能分别保存 / 读取；覆盖不影响其他槽；删除确认可取消；迁移与失败回退有效 |
| 续档对齐 | 两份时间点不同的快照生成不同、闭合且受长度限制的 `<resume_context>`；待续档提示可取消；下一次确认发送只携带一次，拒绝时恢复；人设明确忽略与该时间点冲突的后续旧剧情，界面不声称删除宿主消息 |
| 标签化变量 | 只接受白名单字段与类型 / 范围；未知键、畸形 JSON、越界值不会覆盖上一有效状态；存档与缓存职责分离 |
| 纠错 / 撤销 | 纠错只修改玩家可见白名单字段；未知键不进入状态；有效回合前只保留一个受限撤销点，二次确认后恢复并清除；纠错和撤销后的下一次行动重新对齐模型 |
| 任务 / 线索长表 | 任务的稳定 ID、类型、状态、摘要、紧迫度和关联对象可增量更新；线索来源、发现回合和玩家已知关联随快照恢复；搜索、筛选和无结果状态不泄露未知真相 |
| 引导 / 回归摘要 | 首次引导可前后翻、跳过并从设置重开；长时间离开后的摘要只来自现有纪事，可关闭，不调用模型、不创造新剧情 |
| 纪事 / 状态差异 | `message:done` 后只记录已校验的真实变化；两回合可分别回看，原始机器标签已转为可读句式；随指定存档恢复且有体积上限。未授权真实模型调用时，只能把真实回合链路标为未验证 |
| 玩家档案 | 分开显示宿主昵称 / 头像与游戏称谓 / 属性；有效 `sdk.user.get()` 可读，空值与异常均有明确中文降级；重开档案可安全重读，不抓父页面 DOM、不声称修改宿主人设 |
| 行动检定 | 同一手势只产生一次随机数；属性、难度、目标、掷骰、结果一致，完整标记只填舞台输入框；玩家确认前消息发送数为零，模型约定不重掷 |
| 生命周期 | 重开舞台、重复挂载、切会话、流式更新与 dispose 不重复订阅或发送，不把其他会话状态混入当前会话 |
| 手机可视区 | 320～390px 无横向滚动；短视口输入框仍可达；真机或等价软键盘环境中 `visualViewport` 变化后行动框可见，dispose 后不再响应旧监听。桌面缩窗不能冒充真机验证 |
| 跨规则共享状态 | 用相互独立的脚本作用域加载核心、界面、存档和事件规则；界面修改后的状态与 `sdk.save.set()` payload 必须是同一对象，读回后手动槽、藏页和设置均一致 |
| Canvas / WebGL | 游戏根和画布在 sdk.stage.el() 内，适配尺寸，关闭与销毁释放循环 / 监听 / 资源 |
| 框架生命周期 | Vue / 渲染引擎只挂舞台项目前缀根；重复打开不重复挂载；关闭按设计暂停或卸载，切会话和 dispose 清掉应用、动画、音频、观察器、定时器与 GPU 资源 |
| 外链依赖 | 每项有精确版本、许可证、完整 HTTPS URL、预期全局对象和降级；在目标聊天页验证平台白名单与加载结果。断网或加载失败时核心剧情、舞台输入、确认发送、存档和关闭仍可用 |

## 用户知情与决策检查

规划、功能介绍、现有项目体检或包含多项可选功能的制作任务，再检查：

| 范围 | 可观察的验收条件 |
| --- | --- |
| 需求来源 | 用户已确定、AI 推荐、可选增强、不建议 / 不适用和待决定有明确区分；没有把历史猜测、参考项目功能或推荐默认写成用户要求 |
| 建议质量 | 每个重大建议说明主要收益、代价、风险、可撤销性和不选择时的现状；最多优先展示 3 个高价值决定，允许用户拒绝或延后 |
| 决策边界 | 核心玩法、一点即发、覆盖 / 删除 / 重置、付费调用、外部服务 / 大型依赖、范围扩张和发布没有被 AI 静默代选；“你来定”只授权对应设计项 |
| 功能体检 | 先核对实际文件与页面，再分别列已具备、需要修复、建议优化、可选增强、不适用 / 平台限制和未验证；P0 / P1 / P2 仅表示建议顺序 |
| 决策留痕 | 用户最终选择进入已有需求表、项目记录或版本化设置；拒绝与暂缓项不会在后续被悄悄重新加入，也不反复询问已经确定的选择 |
| 开局视觉信息 | 新复杂项目在视觉信息不足、且用户希望参与选择时，提供已预填的美化与布局需求表；信息已足够不重复询问，用户委托 AI 时披露代选结果而不是把表退回去 |

真实存档写入、切会话、重置、删除和付费消息可能影响用户数据。先用可控本地数据验证；服务端行为只在明确授权的测试范围内执行，不能覆盖用户真实进度以制造测试证据。

## 视觉与隐藏表面

宿主相关任务先读 [host-theme-bridge.md](host-theme-bridge.md)。在真实目标站建立入口清单，区分聊天 iframe、舞台、父页面和独立页面。

完整换肤至少盘点：顶栏、消息正文 / 操作、输入底板 / 文字 / 占位 / 发送、快捷栏、更多功能、模型设置、模型选择、新聊天、对话设置、人设、自定义指令、剧情总结、补充设定与其二级选择器；再加入现场发现的其他入口。

- 盘点不等于逐项执行副作用：导出、重置、创建会话等可能直接操作数据，没有面板时记录真实行为，不为找弹窗而触发它们。
- 动态入口要实际打开，检查真实绘制节点的背景、文字、边框和 selected / focus / disabled 等状态。只在 CSS 文本里搜到选择器不算覆盖。
- 聊天层、游戏层、受支持父层共用一套主题语义；固定平台图标或未接入组件单列限制，不靠本机扩展掩盖。
- 桌面、约 320～390px 窄屏、短视口及长中文分别检查；软键盘和手机真机未测时单列未验证，不能把桌面缩窗写成真机验证。
- 默认保持宿主几何布局与滚动职责；用户明确要求重排时，保留改前证据并对比顶栏、消息列、输入栏、操作按钮与手机表现。
- 文本与按钮检查实际颜色组合，项目可将普通文字 4.5:1、大字与关键图形 3:1 作为最低设计目标。固定白字、渐变底、半透明叠层分别取实际背景评估；不能只检查一对令牌就声称全站合格。
- 句式与中文化检查覆盖选项、空态、错误、设置说明和主剧情；协议标签、编号与 JSON 字段不跟随文案润色改名。
- 多样性检查能从题材、核心循环和信息优先级解释布局；与参考或历史模板相比，结构、排版比例、导航、容器语言和动效至少有两项形成真实差异。只换色、换背景或换圆角不能报为完成新设计。
- 手机不是桌面整体缩小：主要操作、阅读区和状态入口按移动任务重新排序，必要时侧栏转为页签、抽屉或分步视图。

## 性能验证

改动画、模糊、滚动或流式渲染，或用户报告卡顿时执行；单纯改角色名不要求压力测试。

1. 固定设备、浏览器、视口、场景与数据，保持被测标签在前台。先记录旧版基线，再做同条件对照；后台节流样本不得当作渲染回归。
2. 优先测实际症状：页签切换、弹窗开合、长文滚动、输入、流式更新。区分事件处理耗时与帧间隔 / 绘制成本，说明次数、分位数和采用的预算。
3. 检查大面积或叠加 backdrop-filter、持续动画、重复监听、全页 MutationObserver 扫描、stream 回调内全量重绘 / 读写布局 / 存档。
4. 一次对照一个因素，有改善再保留；无效尝试撤回自己的测试改动。低动效 / 低特效模式可减负，但不删核心交互，不重排宿主来凑成绩。
5. 删除临时探针、恢复调试状态；正式版本重新加载后复测。只在开发者工具临时去掉样式不算修复已交付。
6. 报告仍慢的场景和未测设备。一个场景改善不能推断整个网站、所有手机、长历史与真实流式都流畅。

## 完成与交付

输出最少足够的信息：

- 本次完成或查明的内容，以及实际修改的文件（检查任务没有修改则说明）。
- 已运行的命令 / 行为测试与结果；证据位置。
- 本地预览与真实宿主分别验证到哪里，线上是否真的保存。
- 未通过 / 未验证 / 平台限制，以及下一步需要的条件。

制作完成但缺真实宿主环境时可以交付候选文件，标“本地已验证，真实宿主未验证”，不能称已上线或完整验收。静态规则检查、技能格式检查、模型实际遵循表现是三件事。
