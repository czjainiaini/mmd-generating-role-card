# 状态变量、作者存档与缓存

涉及血量、好感度、背包、任务、地图持久化或状态条件世界书时，先确认数据由谁维护，再决定写界面还是写规则。

## 三种数据来源

| 来源 | 适合保存什么 | 与模型 / 历史的关系 |
| --- | --- | --- |
| 平台状态变量 | 已由平台状态结构管理的剧情数值 | 平台可能把当前值带入当轮上下文，并随消息快照回溯；具体启用与导入结构必须以目标站当前资料为准 |
| `sdk.save` 私有存档 | 作者小游戏进度、手动槽、不会自动同步给模型的持久数据 | 不会自动成为模型上下文，也不能用来伪造或重写宿主聊天历史 |
| `sdk.cache` 临时缓存 | 当前展开状态、短暂展示、会话内计算结果 | 刷新即失，不可作为长期进度或剧情真值 |

同一个剧情数值不能同时由平台状态变量和 `sdk.save` 各自独立维护；否则回溯、读档或重生成后容易出现两份真值。传统 `[status]` 文本卡可以解析原文做展示，但不能声称它会自动同步到历史楼层。

## 当前可安全采用的规则

- 游戏自己的长期进度（地图坐标、背包、任务、手动槽、玩家设置）使用一个版本化 `sdk.save` 对象；仅保存白名单字段并做类型、范围和迁移校验。
- 临时弹窗、选择高亮、流式展示等使用 `sdk.cache`；切会话、刷新或读档时重建，而不是依赖缓存恢复。
- 需要模型知晓的读档结果，使用舞台确认发送时附带的、已白名单裁剪的续档上下文；发送失败则恢复待发上下文。不能让前端任意对象覆盖平台剧情状态。
- 如果用户选择平台状态结构，应先取得目标站当前的状态结构配置 / 导出样本，再按样本实现；不要为未知字段猜造导入 JSON。
- 状态变化只更新必要的值和已打开的舞台面板，不要整块卸载、重挂功能栏或用轮询反复写存档。

## 关于 `sdk.vars` 的证据边界

官方最新版写卡资料描述了平台状态变量、`sdk.vars.get()` / `sdk.vars.set()` 与 `vars:change` 的产品方向，但其公开 SDK 契约尚未给出可复现的完整参数、返回值、错误和导入字段定义。本 Skill 的 [authoring/contract.json](../authoring/contract.json) 因此**不收录**这些名称，也不生成依赖它们的运行时代码。

- 只讨论玩法或设定时，可以说明平台状态变量与作者私有存档的职责差异。
- 用户要求可运行状态变量 UI 或状态结构导入时，先读取其提供的新版 SDK 文档、真实导出或目标站公开最新说明；资料不足就交付已确认部分并把状态扩展列为“待接入”。
- 不把推测的 `varSchema`、`varInit` 或世界书变量条件字段塞进正则包；遇到未知扩展字段时停止并说明，不默默删掉数据。

## 验收重点

1. 每项状态只有一个明确真值来源；平台变量、`save` 与 `cache` 不互相冒充。
2. 切会话会取消旧的防抖写入，再读取当前会话的存档，避免延迟写到错误会话。
3. 读手动槽后，界面明确提示“恢复的是游戏快照，旧聊天消息仍在”；续档上下文只在玩家下一次确认行动时发送。
4. 保存失败、状态解析失败或未知字段出现时，保留上一份有效状态并给出可理解反馈，不能阻断文字游玩。

本页记录的是截至 2026-09-18 从官方最新版写卡资料可确认的产品边界；它不替代目标站当前公开 SDK 契约或真实宿主验证。
