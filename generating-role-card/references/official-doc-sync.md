## 后续更新的判定方法

- 已有接口参数先查对应章节；讨论“最新支持什么”时核对目标站当前公开说明。能读取官方新接口不代表获准调用会产生业务副作用的动作。
- 在线有明确增量：记录来源、章节、日期和范围，再同步对应手册 / 契约 / 生成参考。不用较旧 ZIP 整包覆盖本地定制；更新后也不再宣称修改过的文件与原 ZIP 逐字节一致。
- ZIP 提供新的宿主样式资料：记录压缩包指纹、开放根、过滤边界和“资料 / 静态 / 真实宿主”三层证据；不把 archive 中的内部 class 或用户反馈升级为当前站点通用 SDK 契约。
- 文档与现场不一致：分别报告“文档说明”和“本次实测”，保留最小复现。只有通用弹窗表述或搜索无命中时，不能推导特定面板一定支持或永久不支持。
- 现场能找到内部类和旧主题变量，不等于有对角色开放的新 API；公开变量与观察到的组件类名分别记录。
- 官网暂时无法读取：明确采用本包的已注明日期资料，新的能力保持未确认，不猜测接口或同步协议。

## 维护验证

修改契约后，使用本 skill 内 `authoring/scripts/generate-reference.mjs` 重新生成参考表；检查生成一致性、JSON 可解析性、链接可达性及 API / 限额是否被意外修改。有安装版与源包时同步实际改动文件并核对哈希。然后运行 skill 格式校验和现有角色校验器。

这些检查证明文档与工具数据一致，不证明网站已经实现所有主题项，也不证明模型每次都会按技能执行。真实宿主效果与模型行为测试仍分别记证据。
