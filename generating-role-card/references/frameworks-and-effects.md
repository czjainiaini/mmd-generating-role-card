# 框架、特效与外链依赖

制作 Vue 舞台、复杂动画、2D / 3D、音频、富文本或大型状态协议时读取。这里定义选型和验证条件，不把任何第三方库变成每张卡的默认依赖。

## 平台能力边界

新版官方作者文档允许在正则替换内容中写外链 `<script src="…"></script>`：平台按规则顺序加载，同一 URL 只加载一次；只接受 HTTPS，域名还必须在平台白名单中。加载失败不会中断整张卡，而是在 `?sdkDebug=1` 调试面板记录错误。这个机制证明新版可以使用浏览器框架，不证明任意 CDN、任意版本或 ES Module 地址已经获准。

每次采用外链依赖都要记录：库名、用途、精确版本、许可证、完整 URL、预期全局对象、无库时的降级行为，以及本次在哪个真实目标站验证。优先使用固定版本的生产构建和平台已允许的稳定域名；不写 `latest`。经典全局构建通常比动态 `import()` 更贴合平台的顺序加载契约；ES Module 只有在目标站确认 `type="module"`、CSP、净化和浏览器兼容均通过后才用。

大型依赖、外部服务和新增远程资源属于需要用户知情的选择。推荐时说明它改善什么、增加多少加载与维护成本、不选择时保留什么轻量方案；用户没有选择或委托 AI 时，保持原生实现。

## 外链图片、音频与视频

媒体能否使用由多个边界共同决定，必须分开验证：页面 `<meta http-equiv="Content-Security-Policy">`、服务器 HTTP `Content-Security-Policy` 响应头、媒体服务器的状态码 / `Content-Type` / Range 支持、浏览器自动播放策略，以及需要像素读取时的 CORS。浏览器执行的是 CSP 约束的交集；只看页面 meta 或资源中心显示“上传成功”都不能证明角色沙箱可播放。

- 普通 `<img>`、CSS 背景和不读取像素的展示，只需资源能被 CSP 与网络允许；Canvas 读取、PixiJS / Three.js 纹理还要求资源响应提供适合当前沙箱源的 `Access-Control-Allow-Origin`。普通图片显示成功但 Canvas 被污染或匿名加载失败时，只能把该地址用于 DOM / CSS，不能宣称 Three.js 纹理可用。
- 原生 `<audio>` / `<video>` 优先用于背景音乐、环境音和视频。首次播放由玩家点击“进入游戏”“播放”或同等明确控件解锁；提供暂停、静音和音量，记住设置，切会话、关舞台和 `dispose` 时按设计暂停或释放。不要把浏览器拒绝无手势自动播放误诊成平台不支持媒体。
- Howler.js 默认 WebAudio 路径可能通过 XHR / fetch 取音频，因此除 `media-src` 外还受 `connect-src` 影响。目标站只开放 HTTPS `media-src`、而 `connect-src` 仍为 `'self'` 时，使用原生 Audio 或在已确认兼容的 Howler 版本中选择 `html5: true`；只有真实验证后才启用 WebAudio 模式。
- 平台自己的资源中心可能把文件发到另一个资源域名；“平台上传”不等于“与角色沙箱同源”。拿实际直链逐类测试图片、音频和视频。音视频还要检查服务器返回正确 MIME、可加载元数据、可在一次玩家手势后播放；长音频 / 视频检查 Range 请求与拖动。

### 2026-09-10 meimoai15 实测基线

在 `c315928.sbx.meimoai15.com` 的全新无缓存会话中，HTTP 响应头已包含 `media-src 'self' data: blob: https:`。外部 HTTPS MP3 达到 `canplay`，点击后 `play()` 成功；外部 HTTPS MP4 达到 `canplay` 并真实推进播放时间。该结果证明当日该沙箱可用原生 HTTPS 音频和视频，不代表其他域名、后续版本或无手势自动播放永久可用。

同次测试中，`meimoaiimg.com` 图片可由普通 `<img>` 显示，但响应缺少 `Access-Control-Allow-Origin`：非匿名图片绘入 Canvas 后被污染，匿名图片加载失败；支持 CORS 的外部图片则可读取。因此当前该图床可用于普通图片 / CSS 背景，不应直接用于 Canvas、PixiJS 或 Three.js 纹理。服务器 `connect-src` 当时仍为 `'self'`，所以 Howler WebAudio / fetch 路径继续按未通过处理，采用原生媒体或经验证的 HTML5 音频模式。

## 选型阶梯

| 需求 | 首选 | 何时升级 | 不自动加入 |
| --- | --- | --- | --- |
| 普通 HUD、少量弹窗、输入与设置 | 原生 HTML + Vanilla CSS + JavaScript | 页面状态和复用组件明显增多时使用 Vue 3 | Vue、React、大型组件库 |
| 过渡、悬停、选中、数值反馈 | CSS transition / animation、Web Animations API | 需要弹簧、交错序列、复杂 SVG 或可控时间线时使用 Motion | 为几个淡入淡出加载动画库 |
| 2D 粒子、天气、地图、立绘分层 | 原生 Canvas | 场景对象多、需要纹理批处理和持续渲染时使用 PixiJS | 把文字和普通按钮画进 Canvas |
| 3D 场景与镜头 | Three.js | 用户确实选择 3D，且有移动端性能预算 | 用 3D 代替普通背景装饰 |
| 背景音乐、环境音和音效 | 原生 Audio | 多音轨、音频精灵、淡入淡出或跨浏览器控制复杂时使用 Howler.js | 自动播放、无静音与音量设置 |
| 图标 | 审查过的内联 SVG；可从 Lucide 等开放图标集选取所需图标 | 构建流程能按需打包且图标数量很大时再用运行时包 | 为少量图标加载完整图标库 |
| 模型富文本 | `textContent` | 明确需要受限 HTML / Markdown 时，转换后再用 DOMPurify 严格白名单净化 | 把模型输出直接交给 `innerHTML` |
| 状态补丁校验 | 项目字段白名单和类型 / 范围检查 | 深层 schema 很多时用 Ajv 在构建阶段生成独立校验函数 | 在运行时携带完整 Ajv 或接受未知字段 |

Vue 适合组织复杂游戏界面，不是特效引擎。视觉效果仍由 CSS、Web Animations、Canvas、PixiJS 或 Three.js 完成。单舞台内部使用响应式页面状态切换，不默认引入 Vue Router；普通复杂度使用 Vue 自带响应式对象配合 `sdk.save`，不默认引入 Pinia；不默认采用后台管理组件库作为游戏视觉外壳。

## 舞台挂载与生命周期

- 框架、Canvas、PixiJS、Three.js 的唯一应用根都放在 `sdk.stage.el()` 的带项目前缀子节点中；消息气泡只保留轻量、可重建内容
- `sdk.stage.open()` 后再取容器；同一容器只挂载一个应用实例。实例、状态、依赖就绪 Promise、动画控制器、音频和清理函数统一放进 `window.<项目命名空间>`，避免多条脚本规则捕获不同副本
- 普通关闭舞台若要保留页面，暂停动画循环、音频和昂贵观察器，重开后恢复；如果选择在 `stage:close` 完整卸载，下一次打开必须可靠重建
- `conversation:switch` 清理上一会话的瞬时状态并重新读取当前会话存档；`dispose` 必须卸载 Vue、销毁渲染器、停止音频、取消动画帧、观察器、定时器和事件监听
- Vue 使用生产构建；设置 `app.config.errorHandler`，并提供不依赖 Vue 的中文错误壳、返回和继续纯文字游玩的路径
- PixiJS / Three.js 监听实际舞台容器尺寸，不按屏幕宽度猜尺寸；释放纹理、材质、几何体和渲染器。WebGL 不可用时降级为静态背景或 DOM / Canvas 界面
- 音频必须由玩家手势解锁；默认不抢占播放，提供总开关、音量、减少干扰选项，关闭或切会话时符合用户设置

## 加载与降级验收

1. 在本地或隔离夹具验证应用能挂载、更新和销毁，但不把本地成功当成宿主白名单通过。
2. 在目标聊天页加 `?sdkDebug=1`，打开一次舞台，核对外链没有加载错误、精确全局对象存在、应用只挂载一次；创卡页瘦预览不能替代真实聊天页。
3. 外链媒体同时查看页面 CSP meta 与主文档 HTTP CSP 响应头；实际等待图片 `load`、音视频 `canplay`，再在玩家手势中调用 `play()` 并确认播放时间推进。纹理用途另做匿名跨域加载与 Canvas 像素读取测试；普通 `<img>` 成功不能代替纹理验收。
4. 模拟每个外链加载失败。核心剧情、内部输入框、确认发送、存档入口和关闭按钮仍能使用；只有对应增强效果降级。
5. 在桌面与约 320～390px 手机宽度测试首开时间、页签切换、长文滚动、软键盘、后台返回和重复开关舞台。持续动画还要检查减少动效与节能模式。
6. 验收报告分别标记“平台机制有文档”“具体 URL 已验证”“具体功能已验证”。缺少其中一层就标未验证，不能合并成“框架已全面支持”。

## 与宿主换肤的关系

Vue、Motion、PixiJS 和 Three.js 只能控制作者舞台或当前脚本可访问的文档，不能穿透新版跨源父页面。视觉统一通过同一套主题语义完成：舞台组件消费项目令牌，聊天 iframe 映射到公开 `[data-chat]` / `[data-slot]`，父页面白名单弹窗只使用官方主题桥变量。旧版同文档页面仍按其真实版本和选择器单独验证，不能因为舞台用了框架就宣称旧版已同步美化。
