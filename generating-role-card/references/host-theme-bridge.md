# 宿主主题桥与动态面板

宿主换肤、检查隐藏弹窗或判断“其他玩家能否看到”时读取。这里只记录公开作者入口与已观察边界，不授权跨源注入或业务数据操作。

## 先确定目标与文档

记录实际目标域名、聊天页版本、角色 / frame、公开文档与验证日期。SDK 参数先查 skill 内 authoring；主题桥用目标站最新公开作者说明复核，公开文档优先于较旧 ZIP 中缺失的扩展。

截至 **2026-09-05** 的项目证据：新版 sexyai.ai 已开放底栏和白名单父页面弹窗颜色桥，并已把“记忆管理”明确列入范围；旧 h5.aitchat.org “父层都不可覆盖”的结论不能直接沿用。

公开入口：[新版聊天作者说明](https://sexyai.ai/#/pages/docs/ChatVersionGuide)的第 1 章「改底栏和弹窗颜色」及「契约参考 → CSS 变量」。[同步范围与来源](official-doc-sync.md)区分官方基线、在线增量和本地实测。后续网站更新须重新检查，以下覆盖记录不是所有版本的永久承诺。

## 两条不同的路径

1. **直接 CSS**：角色规则里的 style 在聊天 iframe 内，覆盖稳定的 data-chat / data-slot 与 sdk.stage。不能靠父页面 class、提高优先级或 !important 穿透跨源。
2. **官方主题桥**：在角色的 `[data-chat="root"]` 上定义公开白名单颜色，宿主把支持的值同步到部分父页面组件。同步的是颜色，不是任意 CSS、布局、图标或脚本。

因此，同为父页面弹窗也可能一个可换肤、另一个未接入。必须逐个核实；不能一概说“都不支持”，也不能一个变色就声称全部覆盖。

## 已核实的 18 个扩展变量

完整名称与用途以 [contract.json](../authoring/contract.json) 的 `cssVariables.host` 为机器可读来源，[契约参考](../authoring/reference.md#底栏和白名单弹窗)由它生成。可直接改写的完整样式示例在[第 1 章](../authoring/01-style.md#改底栏和弹窗颜色)。这 18 个变量覆盖底栏、快捷按钮、输入框与白名单弹窗，不与基础气泡变量混为一组。

使用可解析的实际颜色值，定义在角色 root；按当前作者文档确认值格式。内层自有组件用同一语义的设计令牌。不要通过修改 SDK contract 编造 theme.set 等不存在的能力。

## 记忆面板：从未接入到已接入的实测

2026-09-05 在同一角色、同一入口复核，在线文档也已把“记忆管理”明确写进“会话列表 / 模型 / 角色资料 / 记忆管理”这一组白名单弹窗。真实页主面板证据：

| 位置 | DOM / 计算样式证据 |
| --- | --- |
| 角色 iframe 根 | `--chat-modal-bg=#101a1b`、`--chat-modal-text=#ede8da`、`--chat-modal-surface=#1c2b2b`、`--chat-modal-accent=#8f713e` |
| 父层记忆面板 | `.summary-sheet.theme-light` 收到 `--background-color=#101a1b`、`--primary-font-color=#ede8da`、`--card-background-color=#1c2b2b`、`--primary-color=#8f713e` |
| 最终绘制 | 面板及外壳为墨青色，正文为米白色，保存按钮为金色；不再是下述 2026-09-04 的白底蓝按钮状态 |

这证明当前目标站的**记忆管理主面板**已经接入角色主题桥；不自动证明编辑态、提示词预设、帮助层、记忆锚点、新增层及所有选中 / 禁用状态均已覆盖。验收仍要实际打开这些二级表面，检查背景、文字、边框和状态对比度。

### 2026-09-04 历史对照

2026-09-04 在 sexyai.ai 新版真实聊天页进行的对照（历史样例，不代替新任务现场检查）：

| 位置 | DOM / 计算样式证据 |
| --- | --- |
| 角色 iframe 根 | `--chat-modal-bg=#101a1b`、`--chat-modal-text=#ede8da`、`--chat-modal-surface=#1c2b2b` |
| 父层模型设置 | 内联覆盖 `--background-color=#101a1b`、`--primary-font-color=#ede8da`、`--card-background-color=#1c2b2b`；背景实际为墨青色 |
| 父层记忆面板 | 根无同类内联覆盖，继承 `--background-color=#FFFFFF`、`--primary-font-color=#212226`、`--primary-color=#17AAFD`；背景白色、保存按钮蓝色 |
| 记忆面板外壳 | 直接父容器 `.u-popup__content` 有内联白色背景 |

当时公开 CSSOM 已显示 `.summary-sheet` 使用父层 `--background-color` / `--primary-font-color`，`.summary-card` 使用 `--card-background-color`，保存按钮使用 `--primary-color`；但角色颜色尚未映射进来。2026-09-05 的文档与真实页证据表明站方随后补接了这一入口。

诊断时比较**变量映射及最终计算颜色**。父层模型和记忆面板的 `--chat-modal-bg` 都可能为空；模型仍会通过旧变量变色，不能单凭该字段为空判失败。`theme-light` 类名本身也不能证明角色主题未生效。

2026-09-04 刷新后的新版文档只写通用白名单，未明确提到记忆管理；2026-09-05 已明确补入。HTML 白名单的 `<summary>` 仍不是记忆接口，`sdk.save` 仍是作者游戏存档，不是平台记忆管理 API；此次变化是父层颜色桥接入，不是新增 memory / summary SDK。

验收至少检查外壳、总开关、自动总结、总结内容及编辑态、字数档位、总结模型、提示词预设和帮助层、记忆锚点及新增层、保存与禁用状态。保持记忆、模型和存档数据不变；实际保存、生成总结等动作仍按用户授权执行。

## 对比度

强调变量可能同时用于按钮背景和小字，而按钮文字固定为白色。逐组合检查，不以“某个主按钮对比合格”冒充所有状态合格。

## 诊断顺序与交付边界

- 先检查目标节点属于哪个 document，再检查实际背景绘制节点、computed style 与变量来源。输入框本体透明不代表其外层白底已消失。
- 主题桥存在时，用已授权范围内的角色配置及真实页证据验证；没有线上写入授权时仅检查并说明可验证到的层级。
- 不使用 window.parent.document、document.domain 或猜测式 postMessage；用户要求公开分发时不安装 Stylus / userstyle，不依赖 localhost。
- 现有线上卡优先只更新相关规则，保留其他人设、规则与数据。只有明确授权保存时才能进入编辑页提交；重新加载后的真实计算样式才是保存生效证据。
- 旧版同文档美化可借鉴视觉和容器类别，但先确认 chatVersion、路由守卫、CSS 根与运行文档，不能原样照搬旧类名。
- 规则包的静态覆盖检查应检查 iframe 内有效选择器及官方变量；无效父页面选择器不计覆盖。父层面板效果以实际打开结果为准。
- 支付、授权、系统安全界面以及独立帮助页不属于角色换肤范围。未支持面板保留原生并记录缺口，等待平台开放，不覆盖或伪造系统控件。
